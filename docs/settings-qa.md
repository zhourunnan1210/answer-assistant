# 设置 · 问答助手

> 路径：主窗口右上角「⚙ 设置」→ 左侧「问答助手」
>
> 这一页配置的是**语音识别（ASR）服务**——把会议/面试里的讲话实时转成文字。
> 问答模式的「回答」始终由「答题模型」页配置的模型生成，本页不管回答，只管"听"。
>
> **v2.3 起主窗口「🎙 问答」按钮暂时下线**：问答是面试模式的子集，
> 统一从「💼 面试」开启监听；本页的 ASR 配置对面试模式同样生效。
> 未配置资料库时面试自动降级为纯问答（不注入个人资料），功能与原问答模式一致。

## 工作方式速览

1. 主窗口点「💼 面试」开启监听（采集**系统输出/扬声器**的声音，不采集麦克风）
2. 听到的讲话实时转写成文字，灰色显示在答案区（「听到：…」）
3. 语气词/杂音碎片（"嗯"、"The." 等）自动过滤，不显示也不触发作答
4. 听到问题后按 `Ctrl+Alt+W` 或点「💬 回答」，生成口语化、结构化的回答

适用场景：腾讯会议 / 浏览器会议中的问答环节、线上答辩、网课提问。

## 识别来源

### 本地模型（默认，强烈推荐）

- 阿里通义 **SenseVoice** 模型，随安装包附带（约 230 MB），首次开启时自动加载（约 1 秒）
- **完全离线**：不需要 Key、不耗流量、毫秒级响应、无隐私顾虑
- 支持中 / 英 / 日 / 韩 / 粤语
- 状态行显示模型是否就绪；显示 ❌ 时说明模型文件缺失（绿色版/源码运行需自行准备 models 目录）

### 云端 API

- 需要联网和 Key，适合不想带模型文件的场景
- **与答题模型同服务商**：仅当答题服务商同时提供语音识别接口时勾选（如硅基流动 SiliconFlow）；Kimi、DeepSeek 等没有语音识别接口，**不要勾选**
- **ASR Base URL / API Key**：独立配置语音识别服务商（与答题模型可以是不同家）
- **ASR 模型**：推荐 SiliconFlow 的 `FunAudioLLM/SenseVoiceSmall`，
  也支持 OpenAI `whisper-1` 等 Whisper 兼容服务
  （免费档偶有冷启动超时，程序会自动重试 3 次）

## 测试语音识别

- 本地模式：加载模型并识别一段 0.8 秒测试音，验证本地链路（显示加载/推理耗时）
- 云端模式：向 ASR 服务发送测试音，验证连通性

**建议配置后必测**，特别是切换来源或更换 Key 之后。

## 问答提示词

问答模式生成回答时用的独立提示词（与答题提示词互不影响）。
默认要求：先判断核心问题 → 第一句话直接给结论 → 分点展开 →
口语化像现场回答 → 150 字以内 → 没有明确问题时给出得体回应。
可按会议类型自定义（如改成技术面试口径、英文会议口径等）。

## 与其他功能的联动

| 功能 | 关系 |
| --- | --- |
| 答题模型 | 问答的「回答」由它生成；本页的 ASR 配置只负责"听" |
| 面试模式 | 开启面试会自动带动问答监听；面试在此基础上增加麦克风通道和资料库上下文 |
| 实时思考 | 问答回答默认关闭思考模式（低延迟），在「通用」页可开 |
| 沉浸式模式 | 问答开启时，鼠标离开窗口自动只留答案区（「通用」页开关） |

## 常见问题

**Q：识别有延迟，讲话过了好几秒才出文字？**
本地模型是毫秒级；出现延迟基本是云端 API 的冷启动/排队导致，
免费档尤其常见。追求速度请用本地模型。

**Q：识别出错字、中英文混杂？**
SenseVoice 对专业术语、人名会有误差，属正常现象——回答模型会结合上下文理解，
问答提示词里已写明"语音识别可能有错别字，请结合上下文理解"。

**Q：会议里对方戴着耳机说话能识别吗？**
问答模式采集的是**系统输出**（你电脑扬声器/耳机里播放的声音），
对方的声音只要你能从电脑上听到，就能识别。你自己的声音不会被采集
（面试模式才采集麦克风）。
